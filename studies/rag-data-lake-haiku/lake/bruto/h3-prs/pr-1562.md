# PR #1562: fix(validate): preserve repeated query values in defineValidatedHandler

Mesclado em 2026-10-03. Autor: 00200200.

## Summary

- `defineValidatedHandler` built its query validation input with `Object.fromEntries(url.searchParams)`, which keeps only the **last** value for repeated keys (`?tag=a&tag=b` → `{ tag: "b" }`).
- Collect repeated keys from `url.searchParams` into arrays (same shape as `getQuery`) before validation, and write array results back as repeated `URLSearchParams` entries. Reading and writing both go through `URLSearchParams`, so decoding matches what the handler sees on `event.url.searchParams`.
- Types: array query fields (e.g. `z.array(z.string())`) are now typed as `string[]` on the validated request instead of `never`.

## Behavior changes

- A query schema like `z.object({ tag: z.string() })` no longer passes for `?tag=a&tag=b` (it used to see `"b"`); the validator now receives `["a", "b"]`. This matches `getValidatedQuery`.
- `EventHandlerRequest["query"]` is widened to `Partial<Record<string, string | string[]>>`, so untyped `getQuery(event)` is now typed `Partial<Record<string, string | string[]>>` — matching what it already returns at runtime for repeated keys.

## Reproduction

```ts
defineValidatedHandler({
  validate: { query: z.object({ tag: z.array(z.string()) }) },
  handler: (event) => event.url.searchParams.getAll("tag"),
});
// GET /?tag=a&tag=b
// before: validation fails / sees only "b"
// after: validator input `{ tag: ["a", "b"] }`, handler returns `["a", "b"]`
```
