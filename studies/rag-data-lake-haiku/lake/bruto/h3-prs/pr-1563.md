# PR #1563: feat: add `h3-v2` alias package

Mesclado em 2026-09-29. Autor: pi0x.

Some package managers treat the common `"h3-v2": "npm:h3@..."` alias (e.g. used by TanStack Start) as a real package name and try to fetch `h3-v2` from the registry. This adds a static `h3-v2` package (on the orphan `h3-v2` branch) that re-exports `h3` so those installs still resolve to h3 v2.

- Static `lib/*.mjs` + `lib/*.d.mts` files, each just `export * from "h3/<subpath>"` (no build step)
- Re-exports all current subpaths: `.`, `node`, `bun`, `deno`, `cloudflare`, `service-worker`, `generic`, `tracing`, `rules`, `rules/cache`, `rules/proxy`, `rules/compiler`
- `.` re-exports bare `h3`, so h3's own runtime conditions (deno/bun/workerd/browser/node) still apply
- Regular dependency `h3: ^2.0.1-rc.32`; forwards h3's optional peers (`crossws`, `ocache`)
- Version mirrors h3 (`2.0.1-rc.32`)

Verified by packing and installing the tarball: every subpath exports the same bindings (identity-equal) as the matching `h3` subpath, and types resolve with `moduleResolution: nodenext`.
