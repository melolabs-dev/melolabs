# PR #1564: fix(static): resolve the MIME type of a precompressed variant from the requested asset

Mesclado em 2026-10-03. Autor: breken-ai.

## Summary

When `serveStatic` is configured with `encodings` and picks a precompressed variant, it guesses the MIME type from the variant's id instead of the requested asset's id. `.gz` and `.br` aren't in the MIME map, so no `content-type` is set, and the runtime falls back to `text/plain;charset=UTF-8`.

```ts
serveStatic(event, {
  encodings: { gzip: ".gz", br: ".br" },
  getMeta: (id) => /* stat(id) → { size, mtime, encoding } (no `type`) */,
  getContents: (id) => /* readFile(id) */,
});
```

`GET /app.js` with `accept-encoding: gzip` serves `app.js.gz` as `text/plain;charset=UTF-8`. The same request without `accept-encoding` serves `app.js` as `text/javascript`. Browsers refuse a module script or a stylesheet served as `text/plain` (strict MIME checking), so turning on precompressed assets breaks the page for every client that sends `accept-encoding`, which is every browser. This affects any `getMeta` that returns `encoding` for precompressed variants but relies on the default MIME map (#1137) instead of returning `type`.

## Fix

`idSearchPaths` now returns each candidate's asset id (the path without the encoding extension) along with the id to look up. The default/custom MIME lookup (`getType`) runs on that asset id, so `app.js.gz` served for `/app.js` resolves to `text/javascript` and `docs/index.html.br` served for `/docs` to `text/html`. A direct request for `/app.js.gz` still resolves from `.gz`, as before. `meta.type` and a `content-type` that's already set still win. One side effect: a custom `getType` that maps `.gz`/`.br` is no longer consulted when a variant is served for the uncompressed path (it now gets `.js`, `.css`, ...).

A `getMeta` that doesn't return `encoding` (like the one in the static assets guide, which returns `{ size, mtime }`) still sends compressed bytes without `content-encoding` once `encodings` is configured; that's a separate follow-up (derive it from the matched encoding, or document the requirement).
