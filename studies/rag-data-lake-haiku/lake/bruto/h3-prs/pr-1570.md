# PR #1570: fix(response): use matching reason phrases in redirect and noContent

Mesclado em 2026-10-07. Autor: giaBaoJS.

`redirect()` labels every status other than 301 with "Found", and `noContent()` labels every status with "No Content". So the phrase is wrong whenever another status is passed:

```js
app.get("/a", () => redirect("/b", 308));
app.get("/c", () => redirect("/d", 307));
app.all("/api/**", (event) => handleCors(event, { preflight: { statusCode: 200 } }) || "ok");
app.use(routeRules({ "/old/**": { redirect: "/new/**" } }));
```

```
$ curl -sI localhost:3000/a | head -1
HTTP/1.1 308 Found
$ curl -sI localhost:3000/c | head -1
HTTP/1.1 307 Found
$ curl -sI localhost:3000/old/x | head -1
HTTP/1.1 307 Found
$ curl -si -X OPTIONS -H 'Origin: https://x.test' -H 'Access-Control-Request-Method: PUT' localhost:3000/api/x | head -1
HTTP/1.1 200 No Content
```

The same label shows up in `res.statusText` for web consumers (`app.request()`, service workers). 307 is also the default status of the `redirect` route rule, so a rule redirect with the default status goes out as `307 Found`.

Reason phrases are only advisory (RFC 9110 section 15: they "can be replaced by local equivalents or left out altogether without affecting the protocol"), but a phrase that belongs to a different code is misleading in logs, curl output and devtools. Neither v1's `sendRedirect` nor `redirect()` before `HTTPResponse` set a phrase, so this came in with the hardcoded defaults.

The fix keeps the existing phrases for 204, 301 and 302 and uses the RFC 9110 phrases for 303, 307 and 308. Any other status gets no phrase, like a plain `200` response today, rather than one borrowed from 302 or 204. An explicit `statusText` passed to `redirect()` still wins.

With the change the same requests return `308 Permanent Redirect`, `307 Temporary Redirect` (also for the rule) and a bare `200`.

Tests (web and node matrix): each redirect status checks its phrase, 300 gets none, an explicit `statusText` is kept, and `noContent(200)` is no longer labelled "No Content". Without the source change, the 303/307/308/300 and `noContent(200)` cases fail with `expected 'Found' to be 'See Other'` (and similar) and `expected 'No Content' to be ''`.
