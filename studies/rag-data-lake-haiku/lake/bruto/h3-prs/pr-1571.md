# PR #1571: fix(node): call `onError` for stream errors in Node.js handlers

Mesclado em 2026-10-07. Autor: kaanisthatyou.

Second item of #1569.

When the stream a `fromNodeHandler` handler pipes into the response errors, the response is already committed, so h3 only logged the error and `onError` never ran.

`fromNodeHandler` now passes the event to `callNodeHandler`, which calls `event.app?.config.onError` with an unhandled `HTTPError` and settles once the hook is done. Since the source emits `close` right after `error`, its `close` listener is removed on that path. The hook's return value is ignored (the response can't change), and an error thrown by the hook is logged. The existing `console.error` stays.

Tests: the existing "fromNodeHandler + piping (with Error and custom status)" test now also checks that `onError` is called once, and a new test checks that an async `onError` finishes before `onResponse`. Both fail on `main` and pass with the change. Full suite: the only failure (`test/unit/cli.test.ts`, `fileURLToPath` on Windows) also fails on `main`. Typecheck and oxlint pass.
