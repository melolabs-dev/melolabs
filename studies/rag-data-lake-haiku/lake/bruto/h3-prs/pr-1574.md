# PR #1574: fix(middleware): pass through handled responses in `onError`

Mesclado em 2026-10-07. Autor: pi0x.

Follow-up to #1571 (part of #1569).

When a stream piped by a `fromNodeHandler` handler fails, the handler rejects with h3's internal `kHandled` signal: the response is already committed and the error has been reported to the app `onError` hook. The `onError()` middleware treated that signal as an error:

- its hook was called with a bogus `HTTPError` 500 (`cause: Symbol(h3.handled)`)
- it re-threw that error, so the app `onError` hook ran a second time
- the error was rendered and its JSON body appended to the already committed response (`item1{"status": 500, ...}` with status 200)

The middleware now re-throws `kHandled` untouched, without calling its hook.

Middleware-registered hooks still do not see stream errors (only the app `onError` config hook does). Reporting them there too would need a separate design.

Test: a new `app.test.ts` case pipes a failing stream with an `onError()` middleware registered. It fails on `main` and passes with the change. Lint, typecheck and the full suite pass.
