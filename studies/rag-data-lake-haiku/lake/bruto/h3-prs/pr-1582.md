# PR #1582: fix(query): decode valid escapes next to a malformed one

Mesclado em 2026-10-17. Autor: harshit-d3v.

when a query value has one malformed escape, `decodeURIComponent` throws and `parseQuery` keeps the whole value undecoded, so the valid escapes stay encoded too. a stray `%` is enough:

```ts
app.get("/search", (event) => ({
  getQuery: getQuery(event).q,
  searchParams: event.url.searchParams.get("q"),
}));
// GET /search?q=caf%C3%A9+50%
// main: {"getQuery":"caf%C3%A9 50%","searchParams":"café 50%"}
// this: {"getQuery":"café 50%","searchParams":"café 50%"}
```

`URLSearchParams` and `node:querystring` both decode the valid escapes and keep the malformed ones as-is. now the catch falls back to that instead of skipping, for keys and values. the happy path doesn't change.

the test compares `parseQuery` with `URLSearchParams` on a few malformed inputs, it fails on main.
