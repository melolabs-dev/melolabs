# PR #1589: fix(cors): make stateful origin regex checks repeatable

Mesclado em 2026-10-17. Autor: xiehuanyi.

Reusing a global or sticky RegExp in the CORS origin array makes permission depend on its `lastIndex`. The same allowed origin can alternate between accepted and rejected requests, and checking an origin mutates the caller's regex state.

For these stateful regexes, check from index zero and restore the previous index in `finally`. Ordinary regexes keep their existing path. Regression cases cover both flags, repeated accepted origins, rejected origins and preservation of a pre-existing index.

Validation on Node 24.21.0:

- Lint, formatting, typecheck and `pnpm build` pass.
- The full unmodified test fixture run reports only the existing loopback IP expectation failure (`::ffff:127.0.0.1`); 3,037 tests pass, 51 skip after `pnpm build` (matching the CI build/test order). Applying the independent loopback test expectation locally allows the full suite to pass (3,038 passed, 51 skipped); that test-only change is excluded from this PR.
