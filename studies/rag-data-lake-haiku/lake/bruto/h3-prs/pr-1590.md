# PR #1590: fix(sse): preserve empty event ids

Mesclado em 2026-10-17. Autor: xiehuanyi.

An SSE message with `id: ""` must send an empty `id` field so an EventSource client can clear its last event ID. The current truthiness check drops that field, leaving the previous reconnection cursor in effect. The [HTML SSE specification](https://html.spec.whatwg.org/multipage/server-sent-events.html#parsing-an-event-stream) defines an empty `id` value as resetting the last event ID.

Check whether the optional ID is a string so empty IDs are emitted and omitted IDs remain omitted. Wire-format regressions cover both a single message and an empty ID following a non-empty ID in a batch.

Validation on Node 24.21.0:
- Both new wire-format cases fail before the fix; all 53 SSE unit and integration tests pass after it.
- Lint, formatting, typecheck and `pnpm build` pass.
- The full unmodified test fixture run reports only the existing loopback IP expectation failure (`::ffff:127.0.0.1`); 3,037 tests pass, 51 skip after `pnpm build` (matching the CI build/test order). Applying the independent loopback test expectation locally allows the full suite to pass (3,038 passed, 51 skipped); that test-only change is excluded from this PR.
